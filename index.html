1. Intro & Rational Agents Lec 01

1.1 核心概念

  • Agent：感知环境（percepts → sensors）并采取动作（actions → actuators）的实体。
  • Rational agent：选择能最大化其期望效用 (expected utility)的动作。注意是"期望"而非保证。
  • Agent function：从 percept 序列到动作的映射；由 agent program 实现。

1.2 环境维度（决定 agent 设计）

维度含义对设计的影响
Fully / Partially observable能否看到完整状态partial → 需要 memory / internal state
Deterministic / Stochastic动作结果是否随机stochastic → 必须处理 contingency
Single / Multi-agent是否有其他 agentmulti → 可能需要随机化策略
Static / Dynamic思考时世界是否变化static → 有时间思考
Discrete / Continuous状态/时间是否离散continuous → 需要 controller
Known / Unknown physics是否知道动力学unknown → 需要 exploration

1.3 Reflex agent vs Planning agent

  • Reflex：仅基于当前 percept（可能加 memory）选动作，不考虑未来。问"世界是怎样的"。
  • Planning：用世界模型模拟"如果...会怎样"，选动作前考虑后果。问"世界会变成怎样"。
  • 区分 optimal vs complete，planning vs replanning。

1.4 PEAS 描述（教材强调）

定义 task environment 用 PEAS：

  • Performance measure — agent 想最大化的效用
  • Environment — agent 行动的场所
  • Actuators — agent 作用于环境的方式
  • Sensors — agent 接收信息的方式

例：自动驾驶车 = (P: 安全到达 / 准时 / 舒适, E: 道路+其他车, A: 方向盘+油门+刹车, S: 摄像头+雷达+GPS)。

2. Uninformed Search Lec 02

2.1 Search Problem 形式化

A search problem = ⟨ states, successor function (action → (next state, cost)), start state, goal test ⟩
Solution = 一系列动作（plan）把 start 变为 goal。
World state vs Search state：world state 包含环境一切细节；search state 只保留 planning 所需的抽象信息。
例：Pacman 吃豆问题，pathing 的 search state 是 (x,y)；eat-all-dots 的 search state 是 (x,y, dot-booleans)。
状态空间大小：12×10 grid + 30 dots + 2 ghosts + 4 朝向 → world: 120·2³⁰·12²·4；pathing: 120；eat-all-dots: 120·2³⁰。

2.2 State Space Graph vs Search Tree

  • State space graph：每个状态出现一次；通常太大，存不下整个图。
  • Search tree：节点是 plans（路径），同一状态可对应多个节点（因不同 path）。
  • 用 fringe（待扩展节点集合）按某种策略扩展。

2.4 Iterative Deepening

结合 DFS 的空间优势和 BFS 的浅层优势：依次跑 depth-limit = 1, 2, 3, ... 的 DFS。看似浪费，但最深层占大部分工作，整体仍 O(bd)。

2.5 The One Queue

DFS / BFS / UCS 仅在 fringe 策略上不同。概念上都是 priority queue；DFS/BFS 可用 stack/queue 避免 log 开销。

Search Gone Wrong：搜索只对模型作用，不在真实世界中尝试 plan。模型不准 → 搜索结果再"最优"也无用。
📝 高频考点 · 搜索基础
  1. 状态空间大小：用乘法原理。例 Pacman（书架排书 36 本）= 36!；不是 2^36（每个位置不是 boolean，是哪本书）。
    原则：状态需要记录能区分不同 plan 后续所需的最小信息。
  2. 分支因子计算：sp24 final Q2 — 6×6 书架，三种动作（右移整行/左移整行/换两本不同行）。
    分支 = 12（6 行 × 2 方向移） + C(36,2)−6·C(6,2) = 540 + 12 = 552。
  3. goal test 是否 valid：检查是否存在非 goal 但通过 test的状态。如"每本书左边是 b_{i−1}"——若两整行互换，每本书相对邻居正确但绝对位置错 → invalid。
  4. 哪些算法保证最优（典型选择题）：BFS（仅当 unit cost）、UCS、A* tree + admissible、A* graph + consistent。DFS 不、Greedy 不、A* w/ 0-heuristic = UCS。
  5. UCS w/ all costs = 1 等价于 BFS。
  6. 状态扩展数（DFS vs BFS）：要会按 fringe 操作顺序模拟。DFS 是 stack（"后进的右子先弹"），BFS 是 queue。给定 maze 算扩展几次后才到 goal。

3. Informed Search & A* Lec 03

3.1 Heuristic

启发式 h(s)：估计 s 到最近 goal 的代价。针对具体问题设计。例：Manhattan / Euclidean 距离、Pancake 中最大未归位煎饼号。

3.2 Greedy vs UCS vs A*

算法优先级说明
UCSg(n) = 已走代价各方向均匀扩展，optimal 但慢
Greedyh(n) = 估计剩余直冲目标，但可能很差（像被误导的 DFS）
A*f(n) = g(n) + h(n)结合两者，主要向目标，但保留全局信息

3.3 A* 何时终止？

只在 dequeue goal 时停，不能在 enqueue goal 时停。否则可能错过更优路径。

🔍 A* 走查（用 Lec 2 的同一张图，h 见蓝字）

步扩展 (f = g+h)Fringe（按 f 排序）说明
0—[(S, f=0+10=10)]初始
1S[(b, 1+4=5), (a, 3+8=11), (c, 9+4=13)]b 的 f 最小，优先
2b[(f, 3+2=5), (e, 9+2=11), (a, 11), (c, 13)]f 和 b 并列最小，按字母 f 先（视约定）
3f[(G, 7+0=7), (e, 11), (a, 11), (c, 13)]G 入队
4G—✅ G dequeued，返回 S→b→f→G, cost = 7（最优）

A* 只扩展了 3 个非目标节点（vs UCS 5 个，BFS 8 个）—— h 把搜索"导向"目标。

关键观察：a 和 c 永远没被扩展。因为 h 告诉我们"经过 a/c 太绕"，f 值始终比经过 b 的路径大。这就是 h 的"剪枝"威力。

🔍 A* 错误终止 vs 正确终止

假设 h(B) = 0（实际到 G 还要 2 步）。如果我们在 enqueue G 时就停，会选 S→B→G（g=3+2=5，G enqueued first via B）。但 正确路径是 S→A→G（g=2+2=4）。必须等到 dequeue G 才停。

3.4 Admissibility (用于 Tree Search)

h 是 admissible (乐观) ⟺ 对所有 s：0 ≤ h(s) ≤ h*(s)（真实最优代价）
定理：若 h admissible，A* tree search 是 optimal。
📐 证明草图（要会复述）

设 A 为最优 goal，B 为次优 goal，假设 B 已在 fringe。令 n 为 A 在 fringe 上的某祖先（也可能是 A 自己）。

  1. f(n) = g(n) + h(n) ≤ g(n) + h*(n) = g(A) = f(A)（admissibility + h=0 at goal）
  2. f(A) < f(B)（A 比 B 更便宜，且二者都在 goal，h=0）
  3. 所以 f(n) ≤ f(A) < f(B)，n 先被扩展 → A 先被扩展 → 最优。

3.5 设计 Admissible Heuristic

  • 放松问题 (relaxed problem)：在更宽松的问题中求最优解 → 一定 ≤ 原问题最优 → admissible。
  • 例 8-puzzle：
    • h₁ = 错位方块数（放松：方块可瞬移）
    • h₂ = 总曼哈顿距离（放松：方块可穿过他物）—— 比 h₁ 更紧。

3.6 Dominance

若 h_a(s) ≥ h_b(s) 对所有 s 成立且 h_a admissible，则 h_a dominates h_b。两个 admissible h 的 max 仍 admissible 且通常更好。零启发 h≡0 退化为 UCS。

3.7 Graph Search

Tree search 重复扩展同一 state → 指数级浪费。Graph search 维护 closed set（已扩展状态），扩展前检查跳过重复。

function GRAPH-SEARCH(problem):
    fringe = {start_node}
    closed = {}
    loop:
        if fringe empty: return failure
        node = pop best from fringe
        if goal_test(node.state): return node
        if node.state not in closed:
            add node.state to closed
            expand: add children to fringe

3.8 Consistency（用于 Graph Search 的 A* 最优性）

h 是 consistent ⟺ 对每条弧 (A → C)：h(A) ≤ cost(A,C) + h(C)
等价：f 值沿 path 单调不降。
Consistency ⟹ Admissibility（反之不一定）。
最优性总结：
  • Tree search：A* 最优 ⟺ h admissible（UCS 是 h=0 的特例）
  • Graph search：A* 最优 ⟺ h consistent
  • 大多数 relaxation 得来的 admissible h 自然也是 consistent。

3.9 A* 缺点 & 变种

A* 需把整个 explored 区域放内存 → 可能爆内存。变种：IDA*（用 f-limit 代替 depth-limit）、RBFS、SMA*。

📝 高频考点 · 启发式
  1. 判断 admissible 的反例法：找到一个状态使 h(s) > h*(s)。常见陷阱：
    • "完成目标需要 N 步" 类启发，当真正最优可能 < N（例 Knight's tour: Manhattan 距离 overestimate，因为骑士一步可跨 2+1）
    • "剩余食物数" 在 Pacman 一格一豆 + 步代价 1 时是 admissible（每豆至少 1 步）
    • "calorie 不够"问题：h = 10−C（剩余卡路里）不 admissible，因为可能一步吃到 100 卡
  2. Consistency ⟹ Admissibility（反之不一定）。反过来选项要选错。
  3. Greedy + consistent ≠ optimal / complete。Greedy 完全不看 g，只看 h。
  4. Trivial heuristic h≡0：A* 退化为 UCS（不会"加速"，只是不变慢）。
  5. max(h_a, h_b) 仍 admissible（若两者都 admissible）；min 不一定。

4. Local Search Lec 04

4.1 何时用 Local Search？

当 path 不重要、goal 配置本身才是答案时（n-queens, TSP）。状态空间 = 所有完整配置；保持一个"当前"状态，迭代改进。常数空间，适合 online。

4.2 Hill Climbing

function HILL-CLIMBING(problem):
    current = initial state
    loop:
        neighbor = best successor of current
        if neighbor.value ≤ current.value: return current
        current = neighbor

"像在大雾里失忆地爬珠峰"。问题：

  • Local maxima：被局部峰困住 → random restarts
  • Plateaus / shoulders：平地 → random sideways moves（但平地上可能死循环）

4.3 Simulated Annealing

偶尔允许"坏"移动，避免被困局部最优。

function SA(problem, schedule):
    current = initial
    for t = 1 to ∞:
        T = schedule(t)
        if T = 0: return current
        next = random successor
        ΔE = next.value - current.value
        if ΔE > 0: current = next        # 永远接受好的
        else:      current = next with prob e^(ΔE/T)   # 概率接受坏的
性质：稳态 Boltzmann 分布 P(x) ∝ eE(x)/T。若 T 降得足够慢（可能要指数慢），收敛到全局最优。VLSI 布线等领域的主力。

4.4 Local Beam Search

K 个并行 local search，每步从所有 K 个状态的子代里挑最优 K 个。关键：和 K 个独立 search 不同 —— 它们"互相沟通"（哪边好往哪聚）。类比：演化。

4.5 Genetic Algorithms

用"自然选择"隐喻：按 fitness 选父代，两两 crossover，加 mutation。

4.6 连续空间

  1. 离散化：用网格 δ 划分。
  2. 随机扰动：hill climbing / SA。
  3. 梯度方法：
梯度向量：∇f(x) = (∂f/∂x₁, ∂f/∂y₁, ...)
极值条件：∇f(x) = 0
Gradient descent：x ← x − α∇f(x)

例：在罗马尼亚选 3 个机场最小化 ∑∑(x_a − x_c)² + (y_a − y_c)²，∂f/∂x₁ = ∑_{c∈C₁} 2(x₁ − x_c) → x₁ = mean of C₁。

5. CSP I — Backtracking & Filtering Lec 05

5.1 CSP 形式化

CSP = ⟨ 变量 X_i, 值域 D_i, 约束 C ⟩
goal: 给所有变量赋值，满足所有约束（identification 问题，path 不重要）。

5.2 例子

问题VariablesDomainsConstraints
Map Coloring每区域{R,G,B}相邻区域颜色不同
N-Queens (Form 1)每格 X_ij{0,1}∑X_ij = N，每行/列/对角线 ∑≤1
N-Queens (Form 2)每列一个 Q_i{1..N}两两不同行/对角
Sudoku每空格{1..9}行/列/3×3区 all-diff
Cryptarithmetic每字母+进位{0..9}列约束 + alldiff

5.3 约束类型

  • Unary：单变量（等价于缩 domain）
  • Binary：两变量（→ binary constraint graph）
  • Higher-order：3+ 变量（如 cryptarithmetic 进位）
  • Preferences (soft)：每个赋值有 cost → 约束优化（之后 Bayes nets 会讲）

5.4 Constraint Graph

节点=变量，边=约束。算法用图结构加速（如 Tasmania 独立 → 整张图能分块解决）。

📊 澳大利亚地图染色的 Constraint Graph

每条边=相邻两州不能同色。Tasmania 是独立子问题（孤立节点）→ 单独解。SA 是"中心枢纽"度数最大。

🎬 Backtracking + Forward Checking 动画式走查

设 Domain = {R, G, B}，按字母序赋值，每次赋值后做 forward checking：

步动作WANTQSANSWV
0初始RGBRGBRGBRGBRGBRGB
1WA = RRGBRGBGBRGBRGB
2NT = GRGRBBRGBRGB
3Q = RRGRBGBRGB
4SA = BRGRBGRG
5NSW = GRGRBGR
6V = R✅ 完整赋值，全部约束满足
FC 的作用：第 4 步赋 SA=B 后，自动从 NSW 划掉 B（剩下 G），从 V 划掉 B（剩下 RG）。如果某 domain 变空就立即回溯。

5.5 Backtracking Search

= DFS + 变量排序 + 边走边查约束。两个核心想法：

  1. 一次只给一个变量赋值（赋值可交换 → 固定顺序）
  2. 每赋一个值就检查与已赋值的冲突（incremental goal test）

5.6 Filtering（核心优化）

Forward Checking

每次赋值后，从所有未赋值变量的 domain 中划掉违反约束的值。如果某 domain 空了，立即回溯。

Arc Consistency (AC-3)

Arc X → Y is consistent ⟺ 对每个 x ∈ D_X，都存在 y ∈ D_Y 使 (x,y) 满足约束。
若不满足，从 tail 删值（即从 D_X 删）。
关键操作：从 X→Y 的尾部 X 删值；X 失去值后，所有指向 X 的弧都要重新检查。
能否检测到 NT 和 SA 都不能蓝？
Forward Checking不能（只看已赋值变量出去的弧）
Arc Consistency能（更早发现失败）

复杂度 O(n²d³)（可优化到 O(n²d²)）。检测所有未来失败是 NP-hard（等价于 SAT）。

Arc consistency 完成后可能：唯一解 / 多个解 / 无解（自己不知道）。所以仍要在 backtracking 内部跑。
📝 高频考点 · CSP（极常考）

1. 判断约束类型（unary / binary / higher-order）

关键：约束同时涉及几个变量。

  • "Hugo 不能在位置 3 或 4" → 只看 Hugo 自己 → unary
  • "Frank 想紧挨 Grace" → 看 F 和 G → binary
  • "Advika 不想任何人挨着她" → 必须检查所有其他变量 → higher-order（"任何人"是关键词）
  • "Iris 不想紧挨 Hugo" → 只 I 和 H → binary（注意区分上一条）

2. LCV + Forward Checking 选值

对每个候选值，模拟"先赋这个值，做 forward checking"，看其他变量 domain 总共少多少。少的就是 LCV。
例：6 个位置给"不想被挨着"的变量，边角(1, 6) 比中间损害小（只挪掉 2 个相邻位置而非 3 个）。

3. AC-3 处理弧 X→Y 后入队哪些弧？

若 X 的 domain 被削减：将所有 (Z → X)（X 的邻居 Z 指向 X 的弧）入队。
注意：不重复入 (Y → X)，不入 (X → ...)。

例：处理 (S → J) 后 S 的 domain 减少 → 入队 (J→S), (M→S)（J,M 都是 S 的邻居）。

4. 处理 (X→Y) 后 X 的 domain 是什么？

对 X 的每个值 x，检查 Y 中是否有合法 y。没有的 x 删掉。
注意"合法"包括所有相关约束（不只是 X-Y 约束，还有 "不能在同位置" 等隐含约束）。

5. Cutset / Residual CSP

  • Cutset 大小 c → 实例化 c 个变量的所有组合（每个 d 个值，共 d^c 种），每种得到一个 residual CSP
  • Residual CSP 可能是也可能不是原 CSP 的解（cutset 赋值可能违反约束）
  • Cutset 的目的：让 residual CSP 的 constraint graph 是树 → O(n·d²) 解

6. K-Consistency 概念题

  • 1-consistent = node consistent（unary 约束满足）
  • 2-consistent = arc consistent
  • Strong n-consistent → 无需 backtracking

6. CSP II — Ordering / Structure / Iterative Lec 06

6.1 K-Consistency

  • 1-consistent (node)：每个变量自身的 unary 约束被满足
  • 2-consistent (arc)：对每对变量，任意单变量赋值都能扩展到另一个
  • k-consistent：对 k-1 变量的任意一致赋值，可扩展到第 k 个变量
  • Strong k-consistency：同时是 k, k-1, ..., 1 consistent
定理：strong n-consistency ⟹ 无需 backtracking 即可解（任意赋值都能扩展）。
代价：建立 strong n-consistency 极其昂贵。考试主要要会 k=2（arc consistency）。

6.2 Ordering 启发式

MRV: Minimum Remaining Values

选 domain 中剩余合法值最少的变量（"most constrained variable"）。Fail-fast：早点发现失败。

LCV: Least Constraining Value

选给定变量后，最少限制其他变量的值。原因：留多点选项给后面，更可能成功。

MRV + LCV + AC 让 1000 queens 可解。

6.3 Problem Structure

独立子问题

若图能分成多个独立连通分量，每个有 c 变量，复杂度从 O(dn) 降到 O((n/c)·dc) —— 线性 n！

Tree-Structured CSP

定理：若 constraint graph 是树，CSP 可在 O(n·d²) 解（vs 一般 O(dn)）。

算法：

  1. Order：选 root，按 parent-before-child 拓扑排序
  2. Backward (remove)：i = n→2，对每个 X_i 做 RemoveInconsistent(Parent(X_i), X_i)
  3. Forward (assign)：i = 1→n，按顺序给 X_i 赋与 Parent(X_i) 一致的值，无回溯

为什么不行于带环图？两个 arc 各自一致，但它们的值可能冲突（"两个 parent 吵架"）。

Cutset Conditioning

找最小变量集，去掉这些变量（实例化）后图变树。Cutset 大小 c → O(dc · (n−c) · d²)。

Tree Decomposition

把图转为"mega-variable"的树，每个 mega-variable 编码原 CSP 一部分；子问题间在共享变量上一致。

6.4 Iterative Improvement (Min-Conflicts)

对完整赋值反复改进：

while not solved:
    挑一个冲突变量
    赋它一个 min-conflicts 值（违反约束最少）
惊人结果：min-conflicts 对随机初始的 n-queens（n 大到一千万）近乎常数时间解决，对几乎所有随机 CSP 也快，除了一个临界比率附近的窄区间。

7.1 游戏分类

  • Deterministic / Stochastic
  • 1 / 2 / N 玩家
  • Zero-sum / general（zero-sum: 一方最大化即另一方最小化）

7.2 Minimax

📊 Minimax 树示例（自下而上计算）

绿三角=MAX，红三角=MIN。从叶往上：MAX 取 max、MIN 取 min。根值 = 8。
def value(state):
    if terminal: return utility(state)
    if MAX's turn: return max-value(state)
    if MIN's turn: return min-value(state)

def max-value(state):
    v = -∞
    for s' in successors(state):
        v = max(v, value(s'))
    return v

def min-value(state):
    v = +∞
    for s' in successors(state):
        v = min(v, value(s'))
    return v

性质：对完美对手最优。对手不完美时？仍然安全但非最优（可能错过抓利用机会）。

效率：和穷举 DFS 一样 Time O(bm), Space O(bm)。象棋 b≈35, m≈100 → 不可能完整求解。

7.3 Alpha-Beta Pruning

🎯 完整 α-β 走查例子

绿色三角=MAX，红色三角=MIN。中间 MIN 节点扫到第一个孩子 v=2 后，因为 2 ≤ α=3，MAX 永远不会选这个分支，所以后两个孩子（×）剪掉。

α-β 模拟步骤（看着上图理解）

  1. 左子树：MAX 调 MIN(α=−∞, β=+∞)；MIN 看 3, 12, 8 → 取 min = 3。返回 3 给 root。
  2. α 更新为 3（MAX 现在至少能拿 3）。
  3. 中子树：MAX 调 MIN(α=3, β=+∞)。MIN 看第一个孩子 = 2。
    • MIN 的 v 现在 = 2，并且 v ≤ α (3) → 触发 α-cut，剩下两个孩子不看
    • 因为：MIN 已经能给 MAX ≤2 的回报，比左边的 3 还差，MAX 不会选这里
  4. 右子树：MAX 调 MIN(α=3, β=+∞)。MIN 看 14, 5, 2 → min = 2。仍 ≤ α，但已经看完，无剪枝可做。
  5. Root 返回 max(3, 2, 2) = 3。共剪掉 2 个叶。

💡 关键直觉

α-cut（在 MIN 节点）
当 MIN 节点的 v ≤ α：
MIN 已经能给 MAX 一个 ≤α 的结果，但 MAX 在别处已有 ≥α，所以 MAX 不会选这里 → 剪。
β-cut（在 MAX 节点）
当 MAX 节点的 v ≥ β：
MAX 已经能拿到 ≥β，但 MIN 在别处能限制为 ≤β，所以 MIN 不会让到这里 → 剪。 
def max-value(state, α, β):
    v = -∞
    for s' in successors:
        v = max(v, value(s', α, β))
        if v ≥ β: return v       # β-cut: MIN 不会让 MAX 到这里
        α = max(α, v)
    return v

def min-value(state, α, β):
    v = +∞
    for s' in successors:
        v = min(v, value(s', α, β))
        if v ≤ α: return v       # α-cut
        β = min(β, v)
    return v
  • α = MAX 在 root→当前路径上的最佳保证
  • β = MIN 在 root→当前路径上的最佳保证
  • 根节点的 minimax 值不变；中间节点可能错（包括根的孩子！所以 naïve 版本不能直接选动作）
  • 完美排序下：Time 从 O(bm) → O(bm/2)，可达深度翻倍
  • 属 metareasoning（推理"该如何计算"）

7.4 Resource Limits & Evaluation Function

真实游戏无法搜到叶 → depth-limited search + evaluation function 替代 terminal utility。

常见形式：线性加权特征
Eval(s) = w₁·f₁(s) + w₂·f₂(s) + ... + w_n·f_n(s)
例：象棋 f₁ = 白后数 − 黑后数 等。
  • 越深越好；eval 不准时，深度可"稀释"误差
  • 用 iterative deepening 做 anytime 算法
  • 好的 eval 还能帮 α-β 排序（more pruning）
Why Pacman Starves：replanning agent 在 horizon 内看不到点数差异时，可能在豆子和"等待"之间反复横跳。

7.5 Monte Carlo Tree Search (MCTS) ⚠️ 课件不重，教材里有，考过

面对 Go 那种巨大分支因子，minimax 不可行 → MCTS。两个思想：

  • Rollout 估值：从状态 s 用某 policy（如随机）模拟到游戏结束很多次，记胜率作为 s 的估值
  • Selective search：不均匀分配 rollout，把更多次试在"有希望"的子节点

UCB1 公式

UCB1(n) = U(n) / N(n)  +  C · √( ln N(parent) / N(n) )
  • N(n) = 经过 n 的 rollout 数；U(n) = 这些 rollout 中 Player(parent(n)) 的胜数
  • 第一项："promising"（exploitation）；第二项："uncertain"（exploration）
  • C 由用户调，平衡探索/利用

UCT 算法（MCTS + UCB）

  1. 用 UCB1 从根往下走，直到到未扩展的叶
  2. 给该叶加一个新孩子，从那里做一次 rollout 得胜负
  3. 沿路回传，更新 N 和 U

重复多次后，选 root 下 N 最大的孩子作为行动。N → ∞ 时 UCT 趋近 minimax。

📝 高频考点 · 博弈树

1. α-β 剪枝模拟题（极常考）

  • 从左到右遍历，prune on equality（即 v ≥ β 或 v ≤ α 时剪）
  • 记口诀：MAX 节点的 v 想≥β 则剪（MIN 不会让到这）；MIN 节点的 v ≤α 则剪
  • 哪些节点被剪？ 模拟一遍，被剪节点 = 完全未访问的
  • 题型：交换两节点值后 0 剪枝 → 数字按"左小右大"顺序排列（ABFDH 这种）
  • α-β 后根值正确，中间值可能错，包括根的孩子

2. 非标准 min（f(x) 变形）

题目可能换成"min |x|"或"min (x−188)²"。关键：

  • 把 hex 节点看作"用 f 排序后选最小 f 对应的孩子"，返回原 x 值给 max
  • 例：孩子 [4,−5,−9,3]，min |x| → |4|=4, |−5|=5, |−9|=9, |3|=3 → 选 x=3
  • 什么 f 等价于标准 min？答：在所有叶值范围内单调递增的 f（如 log, ReLU, e^x, x+5, x−5），不包括 1/x（在正数上递减）

3. 多智能体效用 (multi-agent utilities)

  • terminal 是 utility tuple；每层节点最大化对应分量
  • 一般不能剪枝，因为各玩家目标独立，一个分量的好坏不能限制另一分量

4. MCTS 需要哪些量来算 UCB？（典型多选）
N(s), U(s), N(parent(s))。不需要每个孩子的 N。

5. 评估函数设计 (eval function)
当对手最优时，agent 要避免到达"对手一步赢"的状态。常用：
f(s) = −1 if s 是 "one move from terminal", else 0（任何 a<b 都行）。

6. 何时游戏树无限？
当游戏没有强制终止规则、玩家"理性"地避开必败状态时。例：sp24 排书游戏。

8. Expectimax · Utilities · Rationality Lec 08

8.1 Expectimax

不是对手 vs 我，而是随机结果（骰子、随机 ghost、动作可能失败）。

📊 Expectimax 树示例

圆形=chance 节点。中间节点：v = ½·8 + ⅓·24 + ⅙·(−12) = 4 + 8 − 2 = 10。根=max(10, 7, 5)=10。
def value(state):
    if terminal: return utility
    if MAX: return max-value(state)
    if EXP (chance): return exp-value(state)

def exp-value(state):
    v = 0
    for s' in successors:
        p = P(s')
        v += p * value(s')
    return v
Expectimax 不能像 α-β 那样剪枝（一般地）—— 一个孩子的极端值能拉高/拉低期望，必须看完所有孩子。

8.2 Optimism / Pessimism

用 Minimax用 Expectimax
对随机环境过度悲观对真正对抗环境过度乐观

实验结果：Pacman 用对应算法对应 ghost 表现最好。错配会大幅掉分。

8.3 Mixed: Expectiminimax

如 Backgammon，每个 min/max 之后加一个 chance 层（骰子）。Depth 2 = 20·(21·20)³ ≈ 10⁹。深度越深，单节点对结果影响越小（被概率稀释），所以限深损失也小，但剪枝更难。

8.4 Multi-Agent Utilities

非零和 / 多人游戏：terminal 是效用元组，每个玩家最大化自己的分量。能出现合作/竞争混合。

8.5 MEU Principle

Maximum Expected Utility：rational agent 选 a* = argmax_a E[U(s')|s,a]

8.6 Rational Preferences

满足如下公理 → 行为可由效用函数表示：

  • Transitivity: A≻B, B≻C ⟹ A≻C（违反会被"金钱泵"骗光）
  • Orderability, Continuity, Substitutability, Monotonicity, Decomposability
von Neumann–Morgenstern (1944)：满足这些公理的偏好，存在效用 U 使得：
U(A) > U(B) ⟺ A ≻ B；U(L) = ∑p_i·U(prize_i)。

8.7 Utility Scales & Money

  • Minimax 对效用单调变换不变（只看序）；expectimax 对量级敏感（要算期望）
  • 正线性变换不影响行为
  • 钱本身不是效用，但 U(\$) 是 concave → 人 risk-averse。深陷债务时反而 risk-prone。
  • Insurance：你愿意付 \$100 把 [0.5,\$1000;0.5,\$0]（EMV=\$500）换成确定 \$400 → 保险存在的原因

8.8 Allais Paradox

多数人选 B≻A 且 C≻D，但这违反效用公理 → 真人非完全理性。

📝 高频考点 · Expectimax & 效用
  1. Expectimax 计算：chance 节点 = ∑ p · child。给定概率和孩子值能口算。
  2. Expectimax vs Minimax 选哪个：对手随机 / 环境随机 → expectimax；对手 optimal → minimax；不知道 → minimax 更保守。
  3. Risk-averse：U 是 concave，效用(均值) > 期望(效用) → 愿意付保险费。
  4. 效用是序数还是基数？ 只有确定 prize 比较时是序数；含 lottery（求期望）时要基数。
  5. 哪些变换不改变行为：正线性 aU+b (a>0)；minimax 多接受任何单调变换。

9.3 Discounting

U([r₀, r₁, r₂, ...]) = r₀ + γr₁ + γ²r₂ + ... = ∑ γtr_t
γ ∈ (0,1)；小 γ → 短视

三个理由：

  1. 早奖励通常更有价值
  2. 帮算法收敛（无限和有界）
  3. stationary preferences 定理：满足平稳偏好 ⟺ 加法或贴现效用

9.4 处理无限步

  • Finite horizon：T 步截断（→ 非平稳 policy，依赖剩余步数）
  • Discounting：γ<1 → 有限和
  • Absorbing state：保证每个 policy 都终止

9.5 Optimal Quantities

V*(s) = 从 s 出发按最优策略的期望效用
Q*(s,a) = 从 s 取动作 a，之后最优的期望效用
π*(s) = argmax_a Q*(s,a)

9.6 Bellman 最优方程

V*(s) = maxa ∑s' T(s,a,s') [R(s,a,s') + γV*(s')]
Q*(s,a) = ∑s' T(s,a,s') [R(s,a,s') + γV*(s')]
V*(s) = maxa Q*(s,a)

9.7 Value Iteration

V₀(s) = 0 for all s
repeat:
    for each s:
        V_{k+1}(s) = max_a ∑_{s'} T(s,a,s')[R(s,a,s') + γ·V_k(s')]
until max_s |V_{k+1}(s) − V_k(s)| < ε
  • 每次迭代 O(S²·A)
  • 收敛到唯一 V*
  • V_k(s) 解释为"还剩 k 步可走"时的最优值（depth-k expectimax）
  • Policy 经常比 V 早收敛

9.8 Markov property 形式化（教材）

P(St+1 | St, At, St−1, At−1, ..., S0) = P(St+1 | St, At) = T(s, a, s′)

"给定现在，未来与过去独立"。这就是为何 transition function 只需写 T(s, a, s′)，不依赖历史。

9.9 Discounted utility 上界（教材）

U = ∑t=0∞ γt R(st, at, st+1) ≤ ∑t=0∞ γt Rmax = Rmax / (1−γ)

γ ∈ (0, 1) 保证有界。负 γ 没物理意义（reward 正负交替）。

9.10 Bellman operator 是 γ-收缩（教材完整证明）

定义 Bellman operator B：(BV)(s) = maxa ∑ T[R + γV(s′)]。

||BV − BV′||∞ ≤ γ · ||V − V′||∞
证明步骤（教材逐步推导）

用关键不等式 |max f − max h| ≤ max |f − h|：

|BV(s) − BV′(s)|
  = | max_a Σ T[R + γV(s′)]  −  max_a Σ T[R + γV′(s′)] |
  ≤ max_a | Σ T[R + γV] − Σ T[R + γV′] |      （上面不等式）
  = max_a | γ Σ T(s,a,s′) (V(s′) − V′(s′)) |
  ≤ γ max_a Σ T(s,a,s′) · max_s′ |V(s′) − V′(s′)|
  = γ · ||V − V′||∞                              （T 求和=1）

因为是 γ-contraction，Banach 不动点定理 → V* 唯一，VI 收敛。

9.11 Q-Value Iteration（教材，重要补充）

除了 VI 求 V，也可以直接迭代 Q：

Qk+1(s, a) = ∑s′ T(s, a, s′) [R(s, a, s′) + γ · maxa′ Qk(s′, a′)]

这就是后面 Q-learning 的"目标"。Q-value iteration 需要 T, R；Q-learning 不需要。

10.1 Bellman Equations 复习

10.2 Policy Evaluation

给定 π，求 Vπ。Bellman 退化为无 max的线性等式：

Vπ(s) = ∑s' T(s, π(s), s') [R(s, π(s), s') + γVπ(s')]

两种解法：

  1. 迭代：把上式当更新规则，O(S²) 每轮（比 VI 快，因为只一个 action）
  2. 直接解线性系统：n 个方程 n 个未知数

10.3 Policy Extraction

从 V*（或近似 V）得到 policy：

π*(s) = argmaxa ∑s' T(s,a,s') [R(s,a,s') + γV*(s')]
从 V 抽 policy 要 mini-expectimax（需要 T, R）；从 Q 抽：π*(s) = argmax_a Q*(s,a)，trivial！这是为什么 RL 学 Q 不学 V。

10.4 Policy Iteration

初始化 π₀ 任意
repeat:
    # 1. Evaluation: 算出 V^π_i 直到收敛
    # 2. Improvement: π_{i+1}(s) = argmax_a ∑ T[R + γV^π_i]
until π 不变
对比：
  • Value Iteration：每轮更新 V（隐式更新 π），每轮 O(S²A) 都"贵"
  • Policy Iteration：内层多轮便宜的 PE（O(S²)，固定 π 不取 max）+ 一轮"贵"的 improvement
  • 两者都是动态规划，都收敛到 π*，PI 通常更快

目标方法
算最优 V* / Q* / π*Value Iteration 或 Policy Iteration
评估固定 πPolicy Evaluation
从 V 得 πPolicy Extraction（one-step lookahead）

10.6 Offline vs Online

解 MDP 是 offline planning（要知道 T, R，纯算）。如果 T/R 未知 → 必须真正去"动作"，这就是 RL。RL 关键词：exploration, exploitation, regret, sampling。

📝 高频考点 · MDP
  1. T/R 表行数计算：|S非终态| × |A| × |S′|。注意终态作为 s 不会出现（无动作）。例：2 个非终态 × 3 个动作 × 3 个 s′（含终态） = 18。
  2. 哪行 T=0 / R=N/A：对每个 (s,a)，可能 s′ 不可达 → T=0。bust 动作必到终态 X，所以 (Left, Bust Left, Left) = 0。
  3. terminal state 的 V：恒为 0（无后续 reward）。
  4. 有限/无限 horizon：finite → 非平稳 policy（依赖剩余步数）；infinite + γ<1 → 平稳 policy。
  5. "哪些算法能算 V*?"：
    • VI / PI 需要 T 和 R
    • 给定固定 π 求 Vπ：Policy Evaluation（迭代或解线性系统）
    • 没有 T 但有样本：Direct eval / TD 估 Vπ；Q-learning 估 Q*
  6. γ=1：discounting 无效。如果无 terminal 可能无限 reward；有 terminal 时 OK。
  7. Living reward 调参：越负 → 越想早结束（哪怕扑负 terminal）；越正 → 不想结束（活着就赚）。

11.3 Model-Free: Passive RL

给定 π，估计 Vπ。不是 offline——你真的在 act，但 π 固定。

Direct Evaluation

每次访问 s，记下后续 discounted reward 总和；最终对所有样本平均。

  • ✅ 简单，不需 T/R，最终正确
  • ❌ 浪费状态间连接信息（B 和 E 都到 C，但分别学）→ 慢

Temporal Difference (TD) Learning

sample = R(s, π(s), s') + γVπ(s')
V(s) ← (1−α)V(s) + α·sample
等价：V(s) ← V(s) + α·(sample − V(s))
  • 每次转移都更新（不用等回合结束）
  • Exponential moving average：最近样本权重大；α 逐渐减小可收敛
  • 仍只能评估 π；要选动作需要 T,R 或 Q 值

11.4 Active RL: Q-Learning

不是被动跟 π，而是自己选动作学最优 Q*。

Q-Value Iteration（model-based 视角）

Qk+1(s,a) = ∑s' T(s,a,s')[R(s,a,s') + γ·maxa' Qk(s',a')]

Q-Learning（model-free，sample-based）

收到 sample (s, a, r, s')：
sample = r + γ·maxa' Q(s', a')
Q(s,a) ← (1−α)·Q(s,a) + α·sample
惊人定理：Q-learning 收敛到 Q*，即使你按非最优策略行动（off-policy）。条件：
  1. 探索足够（每个 (s,a) 被访问无限次）
  2. α 最终足够小
  3. 但 α 不能下降太快

12.2 Exploration vs Exploitation

ε-greedy

  • 每步 ε 概率随机，1−ε 概率按当前 policy
  • 能探索全空间，但学完仍乱晃 → 让 ε 随时间衰减

Exploration Function

f(u, n) = u + k/n   （"乐观加成"）
修改 Q-update：
Q(s,a) ← (1−α)Q(s,a) + α·[r + γ·maxa' f(Q(s',a'), N(s',a'))]

未访问够的 (s,a) 给乐观估计 → 倾向于探索；bonus 还反向传播到通往未知的状态。

12.3 Regret

就算最终学到最优，路上犯的错有代价 → regret = 期望损失之和。最小化 regret 比"最终最优"要求更高。Random exploration 和 exploration function 都最终最优，但前者 regret 高。

12.4 Approximate Q-Learning（函数近似）

问题：状态空间太大，Q-table 存不下，也不可能都访问。泛化到相似状态。

Feature-based representation

用一组特征 f₁(s,a), f₂(s,a), ... 描述 (s,a)。例 Pacman：到最近 ghost 距离、到最近 dot 距离、是否在 tunnel 中等。

Q(s,a) = w₁·f₁(s,a) + w₂·f₂(s,a) + ... + w_n·f_n(s,a)

Update（线性回归视角）

difference = [r + γ·maxa' Q(s', a')] − Q(s, a)
w_i ← w_i + α · difference · f_i(s, a)

直观：意外坏事发生 → 减小当时 "on" 的特征对应权重（"怪罪"这些特征）。

  • ✅ 经验压缩成几个权重，能泛化到没见过的状态
  • ❌ 共享特征的状态实际价值可能很不同 → 函数表达力是瓶颈
  • ⚠️ 高次多项式 → overfitting，限制 capacity 反而好

12.5 Policy Search

有时能赢游戏的特征-policy 和最准估 V/Q 的 policy 不一样：

  • Q-learning 优化 modeling（让 Q 接近真值）
  • 动作选择只关心 prediction（Q 值的排序正确就够）

简单 policy search：从 Q-learning 得初始 w，然后爬山调 w：上下扰动 → 跑很多回合看胜率/分数。问题：评估开销大，特征多时不可行。

📝 高频考点 · RL II

1. 哪些 exploration policy 能让 Q-learning 收敛？

需要每个 (s,a) 被访问无限次。所以：

  • ✅ 均匀随机 / ε-greedy（ε>0 不衰减太快）
  • ❌ 总选当前最优（可能永远不试某动作）
  • ❌ 只在 {Buy, Sell} 间选（Hold 概率=0）

2. α = 1 会收敛吗？

不会。α=1 等于"完全替换"旧估计，每次只看最新一个样本，剧烈震荡。要求 α 随时间衰减（但不能太快，如 ∑α=∞ 且 ∑α²<∞）。

3. exploration function 鼓励"少访问"动作的形式

判断 f(u, n) 是否鼓励 explore：当 n 小时 f 大、n 大时 f 小（关于 n 递减）。

f(u, n)鼓励 explore?
u + k/n✅（经典）
1/n✅
e−n · u✅（n 大时压平）
u + n❌（越访问越想去）
u · n❌

4. Approximate Q-learning 更新

difference = [r + γ · maxa′ Q(s′, a′)] − Q(s, a)
wi ← wi + α · difference · fi(s, a)

注意：所有 active feature 的权重一起调，幅度按 fi 缩放。

5. Modeling vs Prediction

  • Q-learning 目标：让 Q 接近真值（modeling）
  • 但只为了选动作时，只需 Q 值排序正确（prediction）
  • 所以 policy search 直接调权重看胜率，往往比"先学 Q 再 argmax"更有效

6. Regret

= 实际累计 reward 与 一开始就最优 累计 reward 的差。即使最终学到最优，"路上犯错"也算 regret。

13. 概率基础 + 独立性 Lec 13

13.1 概率论速通

Possible worlds + Random variables

  • Possible world ω：世界的一种完整可能状态；probability model 给每个 ω 分配 P(ω)∈[0,1] 且 ∑P(ω)=1
  • Random variable X：ω → 值的函数；distribution P(X) 给 X 每个取值的概率

四种概率"形状"

形状例子含义
Joint P(X,Y)P(T,W)所有 (X,Y) 组合的概率
Marginal P(X)P(W)=∑t P(t,W)把 Y 求和掉
Conditional P(X|Y)P(W|T=c)给定 Y 后 X 的分布
Conditional 表 P(X|Y)P(W|T)Y 每个取值各对应一个条件分布

必背公式

Marginalization：P(X) = ∑y P(X, y)
Conditional：P(X | Y) = P(X, Y) / P(Y)
Product Rule：P(X, Y) = P(X|Y) P(Y) = P(Y|X) P(X)
Chain Rule：P(X₁,...,Xn) = ∏i P(Xi | X₁,...,Xi-1)
Bayes Rule：P(X | Y) = P(Y|X) P(X) / P(Y)

Inference by Enumeration

变量分成 query Q, evidence E=e, hidden H：

  1. 选 joint 中与 e 一致的行
  2. 把 hidden 求和掉 → P(Q, e)
  3. Normalize → P(Q | e) = α·P(Q, e)

问题：joint 需要 O(dn) 空间，指数爆炸 → 引出 Bayes Net。

13.2 独立性

绝对独立 X ⊥ Y ⟺ ∀x,y: P(x, y) = P(x) P(y)
等价：P(x | y) = P(x) 或 P(y | x) = P(y)

独立性的威力：n 个独立变量的 joint 从 O(2n) 降到 O(n)。但 绝对独立太罕见。

条件独立 ⭐⭐⭐   X ⊥ Y | Z ⟺ ∀x,y,z: P(x, y | z) = P(x|z) P(y|z)
等价：P(x | y, z) = P(x | z)

直觉："给定 Z 后，Y 不再为 X 提供额外信息" —— Z 屏蔽了 X,Y 之间的关联。

经典例子

  • Traffic / Umbrella / Raining：T ⊥̸ U（看到伞猜可能堵车）；但 T ⊥ U | R
  • Fire / Smoke / Alarm：F ⊥̸ A；但 F ⊥ A | S（火只通过烟雾触发警报）

13.3 Naive Bayes（Ghostbusters）

鬼的位置 G，9 个格子的颜色读数 C1,1,...,C3,3。每个 C 只看与 G 的距离。

关键独立性：给定 G 后，任意两个 C 条件独立：

Cx,y ⊥ Ca,b | G

链式法则展开 + 条件独立简化：

P(G, C1,1,..., C3,3) = P(G) · ∏x,y P(Cx,y | G)

参数：9 × 49 ≈ 230万 → 9 + 9·4 = 45 个。

Naive Bayes 结构：一个 class 变量 + 多个 evidence 变量，evidence 给定 class 后两两条件独立。BN 最简单的特例。

2. 区分边缘 / 联合 / 条件：从 joint 表算 P(A)、P(A|B)、P(A,B)。

3. 判断绝对独立 vs 条件独立：注意两者互不蕴含。

14.2 两套等价语义 ⭐⭐⭐

Global Semantics：P(X₁,...,Xn) = ∏i P(Xi | Parents(Xi))

Local Semantics：每个变量与所有非后代 条件独立 | 父节点
Xi ⊥ non-descendants(Xi) | Parents(Xi)

14.3 D-Separation（独立性判定算法）⭐⭐⭐

Local semantics 只告诉你显然的独立性。D-separation 用图算法读出 BN 蕴含的所有条件独立性。

三种基本路径片段

结构形状Z 未观测Z 被观测
Causal chainX → Z → Yactiveblocked
Common causeX ← Z → Yactiveblocked
V-structureX → Z ← Yblockedactive（或 Z 后代被观测时）
前两种：Z 观测 → 阻断；V-structure：Z 或 Z 后代观测 → 激活（"explaining away"）。
V-structure 反直觉：未观测时 X 和 Y 独立；观测 Z（或 Z 的任一后代）反而不独立。

Explaining away 直觉：B 和 E 本来独立，但听到 Alarm 响了之后，"地震" 和 "入室" 互相竞争解释 alarm → 它们不再独立。

D-Separation 算法

  1. 列 X 到 Y 的所有无向路径
  2. 每条路径拆成 3-节点片段查表
  3. 一条路径 active ⟺ 所有片段 active
  4. 有任一 active 路径 → 不独立；全部 blocked → 独立

14.4 工作例：Alarm 网络

查询分析结论
J ⊥ M ?J ← A → M (common cause), A 未观测 → active不独立
J ⊥ M | A ?A 观测 → blocked独立 ✓
B ⊥ E ?B → A ← E (V), A 及后代 J,M 都未观测 → blocked独立 ✓
B ⊥ E | A ?V-structure, A 被观测 → active不独立（explaining away）
B ⊥ E | J ?V, A 未观测但后代 J 观测 → active不独立

15.1 动机

Inference by Enumeration：P(B|j,m) = α ∑e,a P(B)P(e)P(a|B,e)P(j|a)P(m|a)。对 hidden 变量指数级求和。

α ∑e ∑a P(B)P(e)P(a|B,e)P(j|a)P(m|a)

类比：uwy + uwz + ... + vxz（16乘7加）= (u+v)(w+x)(y+z)（2乘3加）。

15.2 Factor Zoo

• 小写 a, b：变量取某具体值（已锁定）

Factor大写数Entries加起来等于

15.3 两个基本操作

Pointwise Product

新 factor 变量集 = 两个原 factor 变量集的并集。对应 entries 相乘。
(f × g)(x, y, z) = f(x, y) · g(y, z)

不是矩阵乘法！ 类似 database join。⚠️ Factor blowup 风险：P(U,V) × P(V,W) × P(W,X)，10维 → 300 entries 爆到 10000。

Sum Out（消元）

把某变量加掉，factor 变小。
∑J P(A, J) = P(A, j) + P(A, ¬j) = P(A)
为什么先 product 再 sum？
变量 H 散在多个 factor 里，对其中一个单独求和是错的（其他里 H 还活着）。必须先 product 让 H 集中到一个 factor，再 sum out。

15.4 VE 算法骨架

查询: P(Q | E1=e1, ..., Ek=ek)

1. 初始 factors = 所有 CPTs（evidence 实例化）
2. While 还有 hidden variable H：
     a. 收集含 H 的 factors
     b. Pointwise product → 大 factor
     c. Sum out H → 新 factor (不含 H)
     d. 替换原来的 factors
3. 剩下 factors pointwise product
4. Normalize → P(Q | e)

完整例：Burglary 网络查 P(B | j, m)

15.5 消元顺序极重要

考虑 P(D) = α ∑z,a,b,c P(z)P(a|z)P(b|z)P(c|z)P(D|z)（Z 是根，A/B/C/D 是孩子）：

启发式：
• Min-neighbors：选与最少 factor 相关的变量先消
• Polytree（无向树）：从叶子到根，线性时间
• 一般 BN：inference 是 #P-hard

16. Sampling（近似推理）Lec 16

16.1 动机 + 基础积木

VE 在大型 BN 上仍可能太贵。Sampling 用样本频率逼近概率：

P(Q | e) ≈ (满足 e 的样本中 Q 取某值的数量) / (满足 e 的样本总数)

从离散分布采一个值

给 P(C) = {red: 0.6, green: 0.1, blue: 0.3}：

  1. u = random() 抽 [0,1) 均匀样本
  2. 把 [0,1) 切成对应大小区间
  3. u 落哪个区间就采到哪个值（如 u=0.83 → blue）

下面方法都用同一个 Sprinkler 网络：

Cloudy → Sprinkler / Rain → WetGrass
P(C):  c: 0.5,  ¬c: 0.5
P(S|c):  s: 0.1, ¬s: 0.9     P(S|¬c): s: 0.5, ¬s: 0.5
P(R|c):  r: 0.8, ¬r: 0.2     P(R|¬c): r: 0.2, ¬r: 0.8
P(W|s,r): w: 0.99    P(W|s,¬r): w: 0.90
P(W|¬s,r): w: 0.90   P(W|¬s,¬r): w: 0.01

16.2 Prior Sampling

完全不看 evidence，按拓扑序按 CPT 采：

for X_i in topological_order:
    sample x_i ~ P(X_i | parents(X_i))

采一个样本

  1. C ~ P(C), u=0.37 → c
  2. S ~ P(S|c)=[s:0.1, ¬s:0.9], u=0.42 → ¬s
  3. R ~ P(R|c)=[r:0.8, ¬r:0.2], u=0.65 → r
  4. W ~ P(W|¬s,r)=[w:0.9, ¬w:0.1], u=0.21 → w

样本：(c, ¬s, r, w)。

Consistency：样本产生概率 = ∏ P(xi | parents) = joint distribution → 频率收敛真概率。
局限：估不了条件概率（不带 evidence）。

16.3 Rejection Sampling

Prior sampling + 早期拒绝不符 evidence 的样本：

for X_i in topological_order:
    sample x_i ~ P(X_i | parents(X_i))
    if X_i 是 evidence 且 x_i ≠ 观测值:
        return REJECT

用被接受的样本数频率估 P(Q | e)。

致命问题：evidence 罕见时拒绝率爆炸。P(e)=0.001 → 1000 个样本只接受 1 个。

16.4 Likelihood Weighting ⭐ 重点

核心想法：别扔样本！强行让 evidence 取观测值，用权重修正"作弊"。

w = 1.0
for X_i in topological_order:
    if X_i 是 evidence:
        x_i = 观测值                       # 钉死
        w *= P(x_i | parents(X_i))         # 累乘权重
    else:
        sample x_i ~ P(X_i | parents(X_i))

例：算 P(R | s, w)

  1. C: 采 → c
  2. S evidence! 钉死 s。w *= P(s|c)=0.1 → w=0.1
  3. R: 采 ~ P(R|c) → r
  4. W evidence! 钉死 w。w *= P(w|s,r)=0.99 → w=0.099

样本 (c, s, r, w), 权重 = 0.099

用加权样本估条件概率

P̂(Q=q | e) = (∑样本 Q=q wj) / (∑所有样本 wj)

Consistency

未加权 ∏ P(zj|Pa) 缺 evidence CPTs；权重 w = ∏ P(ek|Pa(Ek)) 恰好补上 → 加权概率 = P(z, e)。

致命弱点：上游变量看不到 evidence。采 C 时还按 P(C) 采，没用 s。
Evidence 多/在叶子时，权重 ~ O(smallk)，少数样本主导平均，方差极大。

16.5 Gibbs Sampling / MCMC ⭐⭐⭐

彻底换思路：维护一个完整状态，每次只重采一个变量，慢慢游走。

初始化:
    fix evidence 变量为观测值（永不变）
    randomly initialize 其他变量

repeat:
    pick a non-evidence variable X_i
    sample x_i' ~ P(X_i | all other variables 当前值)
    update state[X_i] = x_i'
    record state as a sample
Markov Blanket(Xi) = parents + children + children's other parents (co-parents)

P(Xi | all others) = P(Xi | MB(Xi))
    ∝ P(Xi | Pa(Xi)) · ∏C ∈ children(Xi) P(C | Pa(C))
MB(X) = {P₁, P₂, C₁, C₂, O₁, O₂}：父 + 子 + 子的另一对父。给定 MB，X d-separated from 网络其他部分。

例：P(R | s, w) 上跑 Gibbs（Sprinkler 网络）

计算两个 MB：

  • MB(C) = {S, R}; P(C | s, R) ∝ P(C) · P(s|C) · P(R|C)
  • MB(R) = {C, S, W}; P(R | C, s, w) ∝ P(R|C) · P(w|s, R)

初始 (c, s, r, w)。重采 C：

  • P(c|s,r) ∝ 0.5 · 0.1 · 0.8 = 0.04
  • P(¬c|s,r) ∝ 0.5 · 0.5 · 0.2 = 0.05
  • Normalize: P(c|s,r) ≈ 0.444, P(¬c|s,r) ≈ 0.556

Consistency

每步是 Markov chain 转移 πt+1 = Kπt。Equilibrium Kπ = π，唯一不动点是 π = P(· | e)。条件：chain ergodic（CPTs ∈ (0,1)）。

✅ Evidence 影响所有变量（通过 MB 全局影响）
✅ 大型 BN 实战首选（BUGS, JAGS, STAN）
❌ 需要 burn-in 扔掉前期样本
❌ 样本相关（不独立）
❌ Deterministic CPT 时收敛慢

17. Markov Models · HMMs · Forward · Viterbi Lec 17

17.1 Markov Model 定义

把一个变量随时间复制成一串：X0 → X1 → X2 → ...。每个 Xt 是 t 时刻的状态。

Markov Property（memoryless）：未来只依赖现在，不依赖过去
Xt+1 ⊥ {X0,...,Xt-1} | Xt

Stationarity：P(Xt+1 | Xt) 对所有 t 相同（只需一张转移表）

Joint：P(X0,...,XT) = P(X0) · ∏t=1..T P(Xt | Xt-1)
Markov chain：每步只看前一步。

例：天气

P(X_0):  sun: 0.5,  rain: 0.5

P(X_t | X_{t-1}):
  X_{t-1}=sun:  X_t=sun 0.9,  X_t=rain 0.1
  X_{t-1}=rain: X_t=sun 0.3,  X_t=rain 0.7

17.2 Mini-Forward Algorithm ⭐

问题：不给 evidence，只问 P(Xt)。朴素办法 O(dT) 指数；递推 O(T·d²)。

P(Xt+1) = ∑xt P(Xt+1 | xt) · P(xt)

直觉：对每个当前状态 xt，按转移概率推到下一时刻，加权求和。

17.3 Stationary Distribution ⭐

随 t → ∞，P(Xt) 收敛到 P∞（与初始分布无关，ergodic 条件下）：

P∞(x') = ∑x P(x' | x) · P∞(x)    且   ∑ P∞ = 1

解法（textbook 例：sun→sun 0.6, rain→sun 0.1）

设 x = P(sun), y = P(rain) = 1−x：

0.6x + 0.1(1−x) = x
0.5x + 0.1 = x
0.1 = 0.5x
x = 0.2

→ P∞ = (sun: 0.2, rain: 0.8)。

Ergodic 条件：connected + aperiodic。所有转移概率严格在 (0,1) 之间就够。
应用：Google PageRank（网页跳转 Markov chain，stationary = "重要性"）。

关于 diffusion 直觉（Ghostbusters）

Transition 类型没 evidence 时 belief 演化
随机 (到 neighbor)概率质量扩散 → 趋向均匀，不确定性增加
确定 (沿环走)belief 平移/旋转，形状不变（chain periodic，不收敛）

17.4 Hidden Markov Models (HMM)

真实场景：state 通常不可直接观察，只能通过带噪 sensor 间接观测。

HMM：隐藏状态 X 链 + 每步一个观测 E。X 之间是转移，X→E 是 sensor。
HMM 由三件套定义：
• Initial: P(X0)
• Transition: P(Xt | Xt-1) （stationary）
• Sensor: P(Et | Xt) （stationary）

Joint: P(X0:T, E1:T) = P(X0) · ∏t=1..T P(Xt|Xt-1) P(Et|Xt)

HMM 关键独立性

  • 未来 ⊥ 过去 | 现在：Xt+1 ⊥ X0:t-1 | Xt
  • 当前观测 ⊥ 其他一切 | 当前状态：Et ⊥ rest | Xt
  • 注意：E 之间不独立（通过共享 X 链相关）

四种推理任务

任务定义用途
FilteringP(Xt | e1:t)当前 belief state（最常考）
PredictionP(Xt+k | e1:t), k>0未来状态预测
SmoothingP(Xk | e1:t), k<t用未来 evidence 修正过去
Most Likely Explanationargmaxx1:t P(x1:t | e1:t)最佳状态序列（Viterbi）

17.5 Forward Algorithm（Filtering）⭐⭐⭐

维护 belief B(Xt) = P(Xt | e1:t)。每个时间步两个动作：

Step 1 - Time Elapse (Predict)：incorporate transition
B'(Xt+1) = ∑xt P(Xt+1 | xt) · B(xt)

Step 2 - Observation Update：incorporate evidence
B(Xt+1) ∝ P(et+1 | Xt+1) · B'(Xt+1)

合起来：B(Xt+1) ∝ P(et+1 | Xt+1) · ∑xt P(Xt+1 | xt) · B(xt)
两阶段的角色：
  • Time elapse 让 belief 因 transition 扩散 → 信息变模糊
  • Observation update 让 belief 因 evidence 集中 → 信息变 sharp
  • 两者互相拉扯：transition 让你忘记，observation 让你想起来

完整推导（B(Wt) → B(Wt+1)）

从 marginal + chain rule + HMM 独立性：

P(X_{t+1} | e_{1:t+1})
  = α P(e_{t+1} | X_{t+1}, e_{1:t}) P(X_{t+1} | e_{1:t})    [Bayes]
  = α P(e_{t+1} | X_{t+1}) P(X_{t+1} | e_{1:t})              [E_{t+1} ⊥ e_{1:t} | X_{t+1}]
  = α P(e_{t+1} | X_{t+1}) ∑_x_t P(X_{t+1} | x_t) P(x_t | e_{1:t})    [condition on x_t]

走例：天气 HMM

P(W_0) = [sun: 0.5, rain: 0.5]
Transition: P(W_t | W_{t-1})
  sun → sun 0.9,  sun → rain 0.1
  rain → sun 0.3, rain → rain 0.7
Sensor: P(U_t | W_t)
  sun:  U=true 0.2, U=false 0.8
  rain: U=true 0.9, U=false 0.1
步动作B(sun)B(rain)
t=0初始0.50.5
t=1 predictB'(W₁) = 0.5·[0.9,0.1] + 0.5·[0.3,0.7]0.60.4
t=1 update u₁=T·P(U=T|W) = 0.6·0.2, 0.4·0.90.12 → 0.250.36 → 0.75
t=2 predict0.25·[0.9,0.1] + 0.75·[0.3,0.7]0.450.55
t=2 update u₂=T0.45·0.2, 0.55·0.90.09 → 0.1540.495 → 0.846

每步先 predict 再 update，update 后 normalize（除以 ∑）。Normalize 可以延后到最后一次性做。

矩阵形式

f1:t+1 = α · Ot+1 · TT · f1:t

其中 T 是 transition matrix，Ot 是 sensor matrix（diagonal: P(et | X) for each X）。每步 O(|X|²)。

17.6 Viterbi Algorithm（Most Likely Explanation）⭐⭐⭐

问题：找最可能的状态序列（不是某时刻的边缘分布）：

argmaxx1:T P(x1:T | e1:T) = argmax P(x1:T, e1:T)
    = argmax P(x0) · ∏t P(xt | xt-1) P(et | xt)

State trellis（关键可视化）

State trellis：每列一个时间步，每个状态一行。红色 = 最佳路径（Viterbi 找的就是这条）。每条边权重 = P(xt|xt-1) · P(et|xt)。

Forward 与 Viterbi 对比

Forward (filtering)Viterbi (MLE)
问题P(Xt | e1:t)argmax P(x1:t | e1:t)
聚合操作∑ (求所有路径的和)max (找最佳路径)
递归ft+1 = α·P(et+1|Xt+1)·∑xt P(Xt+1|xt)·ftmt+1 = P(et+1|Xt+1)·maxxt P(Xt+1|xt)·mt
记录每个 state 的总概率每个 state 的最优路径概率 + back-pointer

Viterbi 算法

定义 m_t[x_t] = max_{x_{1:t-1}} P(x_{1:t}, e_{1:t})
       a_t[x_t] = 来到 x_t 的最佳前置 state（back-pointer）

前向 pass:
    m_0[x_0] = P(x_0) · P(e_0 | x_0)
    for t = 1, 2, ..., T:
        for each state x_t:
            m_t[x_t] = P(e_t | x_t) · max_{x_{t-1}} P(x_t | x_{t-1}) · m_{t-1}[x_{t-1}]
            a_t[x_t] = argmax_{x_{t-1}} P(x_t | x_{t-1}) · m_{t-1}[x_{t-1}]

后向 pass（回溯）:
    x_T* = argmax_{x_T} m_T[x_T]
    for t = T-1, T-2, ..., 0:
        x_t* = a_{t+1}[x_{t+1}*]
返回 x_{0:T}*

复杂度

  • 时间：O(|X|² · T)
  • 空间：O(|X| · T)（要存所有 back-pointer 才能回溯）
  • 暴力枚举所有路径：O(|X|T) —— Viterbi 用 DP 把指数压成多项式
Viterbi 本质 = breadth-first graph search on trellis。在 negative log probability 空间，argmax ∏ = argmin ∑ → 变成最短路径问题。也可以用 A* 加速（如果有 admissible heuristic）。
📝 高频考点 · Lec 17（必考）

1. Mini-Forward 几步：给 P(X₀) 和 transition table，手算 P(X₁), P(X₂), ...

2. 解 Stationary Distribution：列两个方程（守恒 + 总和=1），解一元一次方程。

3. Forward Algorithm 一步：给 B(Xt), transition, sensor, et+1，求 B(Xt+1)。套路：

(a) Predict: B'(X_{t+1}) = ∑_x_t P(X_{t+1}|x_t) · B(x_t)     # 别 normalize
(b) Update:  B(X_{t+1}) ∝ P(e_{t+1}|X_{t+1}) · B'(X_{t+1})
(c) Normalize

4. Viterbi 一步：给 mt, transition, sensor, et+1，求 mt+1 和 back-pointer。注意是 max 不是 ∑。

5. Forward vs Viterbi：什么时候用哪个？filtering 用 forward（∑），最可能状态序列用 Viterbi（max）。Filtering 给的不是 MLE 序列！每个时刻边缘最大不等于整体序列最大。

6. HMM 独立性：判断 ei ⊥ ej？Xi ⊥ Xj | Xk？用 d-separation 在展开的 HMM BN 上判。注意：E 之间一般不独立（通过 X 链相关）。

7. Diffusion 直觉：随机 transition → belief 扩散；确定 transition → belief 平移不变形。Time elapse 让 belief 模糊，observation 让 belief sharp。

Game Search

  • Minimax: O(b^m)，对最优对手最优
  • α-β: 完美排序 → O(b^{m/2})；只保根值正确
  • α = MAX 沿 path 的最佳；β = MIN 沿 path 的最佳
  • Expectimax: 用 chance 节点，期望平均；无法剪枝
  • Expectimax 对效用量级敏感；Minimax 对单调变换不变
  • MCTS UCB1: U(n)/N(n) + C·√(ln N(parent)/N(n))；UCT 选 N 最大的孩子
  • Multi-agent utility tuple → 一般不能剪枝

MDP 公式

Bellman 最优：V*(s) = maxa ∑s' T(s,a,s')[R(s,a,s') + γV*(s')]
Q*：Q*(s,a) = ∑s' T(s,a,s')[R(s,a,s') + γ·maxa' Q*(s',a')]
Policy：π*(s) = argmaxa Q*(s,a)
Policy Evaluation：Vπ(s) = ∑s' T(s,π(s),s')[R + γVπ(s')]
Discounted utility：U = ∑ γt·r_t

RL 公式

TD value：V(s) ← V(s) + α·[r + γV(s') − V(s)]
Q-learning：Q(s,a) ← Q(s,a) + α·[r + γ·maxa' Q(s',a') − Q(s,a)]
Approx Q：w_i ← w_i + α·[r + γ·maxa' Q(s',a') − Q(s,a)]·f_i(s,a)
Exploration f：f(u, n) = u + k/n

常考易错点

  1. A* 终止条件：dequeue goal 时停，不是 enqueue
  2. Tree search 用 admissible，Graph search 要 consistent
  3. Arc consistency 从 tail 删值
  4. MRV 选最少剩余值（fail-fast），LCV 选最少限制其他
  5. α-β 中间节点值可能错，包括根的孩子 —— naïve 版不能直接选动作
  6. Expectimax 对效用量级敏感，minimax 不
  7. Policy 通常比 V 早收敛
  8. 从 Q 抽 policy trivial，从 V 抽要 mini-expectimax
  9. Q-learning 是 off-policy：随便走都能学到 Q*（前提：探索充分）
  10. Discount γ<1 保证收敛，也表达"早奖励更值钱"
  11. Forward checking 检测不到所有失败（如 NT 和 SA 都不能蓝），AC 能
  12. Bellman update 在 VI / PE / PI 里本质都是 one-step expectimax
